# Codex request — harden the foundation, then prove source-independent inheritance

## Objective

Strengthen Forever Works as a dependable neutral foundation before expanding its vocabulary. Read AGENTS.md, docs/STANDARD.md, docs/API/PUBLIC_API_V0_1.md and [the readiness audit](../docs/RESEARCH/FOUNDATION_READINESS_AUDIT_2026-10-15.md). Preserve unknown-field compatibility, accepted provenance, old-version fixtures, JavaScript's independent proof target and honest UNKNOWN behavior.

This request proposes two bounded runs. Do not substitute generated documentation volume for executed behavior.

## Run A — make existing promises consistent

1. Reproduce audit findings F1–F4 and capture tests before fixes. Include invalid IDs, malformed/unsupported/mismatched versions, wrong field types/enums, invalid provenance, manifest structure, duplicate inventory paths and reference errors for every actual reference field, including undotted IDs. Decide ambiguous reference-versus-prose semantics from authoritative documents; record unresolved ambiguity rather than broad heuristics.
2. Align core runtime validation with authoritative schemas and semantic constraints across JavaScript, Python and TypeScript. Use an independent Draft 2020-12 oracle for the same fixture corpus, including the self-model and examples. Preserve schema-valid unknown fields; do not require arbitrary new metadata to fix existing defects. Keep plain JavaScript consumers independent of TypeScript.
3. Define portable normalization precisely and compare independently generated results across implementations on mixed case, punctuation, non-ASCII, integer-like keys, arrays and numeric boundaries. Preserve existing valid fixtures where the contract is unchanged. If a real semantic change is necessary, propose/version it with compatibility evidence rather than quietly changing the standard.
4. Replace unsafe/incomplete C JSON handling. Reject malformed or missing records instead of dropping them; enforce containment and bounded resource use. Run all applicable shared negative fixtures through C and its C++ wrapper. Explicitly document any remaining unsupported operations instead of advertising full conformance.
5. Harden core loaders: actual target containment, safe manifest paths, input bounds, UTF-8/JSON errors and defined trusted-checkout assumptions. Use safe deterministic failures; never execute commands or follow evidence URIs just because a model names them.
6. Clarify claim aggregation versus independently verified evidence (F5). Preserve existing published behavior unless reviewed/versioned. Improve audit/report terminology so a declared PASS cannot be mistaken for a verified runtime result. Do not implement arbitrary command execution as an evidence verifier.
7. Expand CI beyond current smoke/normalization checks: full shared applicable corpus per advertised binding, schema oracle, stable errors, normalization goldens and relevant malformed input regressions. Keep all implementation-specific proof scopes explicit.
8. Update official API docs whenever semantics/error/adapter obligations change, plus conformance, binding status and self-description evidence. Provide exact commands, results, remaining unknowns and artifact digests.

Acceptance: existing baseline plus new adverse cases pass; independent schema/runtime discrepancies are resolved or explicitly blocked; documented normalization matches independent outputs; core loader containment is tested; no falsely promoted cross-language/runtime claims. No unrelated product features, new standard taxonomy or large speculative API layer.

## Run B — small real inheritance experiment

Only after the core acceptance gates hold, define a bounded portable inheritance-package convention using the existing model/profile mechanisms where possible. Label any new profile experimental; do not add canonical kinds without reviewed necessity.

Build two small, separately running participants with documented behavior, formats, identity, authority, state ownership, errors, retries, version compatibility and safe controlled effects. Export complete checksummed documentation packages with fixtures, rationale and actual implementation descriptions. Do not include source implementation code as a disguised required dependency.

Give a fresh construction agent the broad task of creating a useful third complementary participant. Deny access to the original repositories and hidden coaching; record allowed platform references, toolchains and reference service access. New implementation code and standard third-party tools are allowed. Use a separately operated acceptance environment and held-out cases based on published contracts to verify interaction with both participants.

Measure real data round-tripping, metadata preservation, authority, recovery and target usability—not screenshots alone. Record missing knowledge, human interventions, time/compute and all failures. An agent's economic hypothesis is not measured revenue. Structural profile validity must remain separate from runtime acceptance.

Deliver the third working participant, its own inheritance package and independent evidence. If no independent construction/evaluation setup is available, ship the harness and report the cold trial NOT_RUN; never fabricate independence or substitute the same agent's private memory for the package.

## Follow-on decision

Use observed gaps to decide whether the standard needs a small optional profile, better authoring guidance or an API extension. Repeat on dissimilar tasks and with independent adopters before broadening compatibility claims. Atlas/Redown Android is an eventual real-world target, not a shortcut around this proof.

A foundational standard earns trust through precise semantics, reproducible independent implementations and useful adoption. The ambitious vision remains; this run supplies the missing evidence.
